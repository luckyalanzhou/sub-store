# sub-store 使用笔记

## 安装

从 [GitHub Releases](https://github.com/luckyalanzhou/sub-store/releases/latest) 下载 `.run` 自解压安装器，在 **iStore → 手动安装**上传并安装。安装器面向 iStoreOS 24.10.x（opkg 系统）。

Release 同时提供 `.sha256` 校验文件，可用于手动验证下载完整性；LuCI 自动更新会自行下载该文件。它只校验文件完整性，不是发布者签名。

首次安装时自动安装依赖、联网拉取官方最新镜像并启动容器；即使本地已有镜像也会执行拉取，拉取失败则停止部署。

默认前端端口为 `3001`，后端 API 端口为 `3000`，两者必须不同。

`.run` 安装失败时查看：

```sh
cat /tmp/sub-store-run-install.log
```

## 打开管理界面

进入 **服务 → sub-store**，服务启动后在管理地址旁点击 **打开**。

管理地址带有 `?api=` 参数，必须使用完整地址。地址中的 `%3A`、`%2F` 是正常编码，不要删除或改成后端直连地址。

```sh
sub-storectl url      # 管理地址
sub-storectl api-url  # 后端地址
```

后端局域网直连关闭时，`api-url` 显示 `127.0.0.1`，只用于路由器本机诊断；日常访问和复制请使用 `sub-storectl url`。

前后端在同一容器的不同端口运行；管理页面通过前端转发访问 API。

## LuCI 设置

- **管理页面端口**：默认 `3001`。
- **访问主机名**：可填域名或 IPv4，不带协议和端口；留空使用 LAN 地址。
- **公开访问地址**：HTTPS、反向代理或外部端口不同时填写完整地址，例如 `https://sub.example.com`。
- **后端 API 端口**：默认 `3000`，必须与前端端口不同。
- **允许局域网直连后端**：新安装默认关闭；管理页面仍通过前端端口访问 API。旧版升级会保留原来的直连行为。
- **API 密钥**：管理 API 的随机路径；轮换后旧地址失效。
- **同步计划**：默认每天北京时间 23:55；只运行 Sub-Store 中已启用的同步任务。

点击 **保存并应用** 会保存设置并重启容器；点击 **保存** 只保存，不重启。
启动、停止和重启按钮只控制 Sub-Store 服务。

## Sub-Store 功能

订阅、组合、文件、脚本和同步任务都在官方 Web 界面管理。GitHub Gist 等同步凭证也在 Sub-Store 中设置。

[官方使用文档](https://sub-store-org.github.io/doc/)

## 日志

- **日志**页下方可切换两个标签：运行日志为 Sub-Store 容器日志；维护日志为 LuCI 发起的启动、停止、重启和更新操作记录。安装失败日志单独保存在 `/tmp/sub-store-run-install.log`。
- 日志页按需自动刷新；每类日志最多保留 `1 MiB`。维护日志位于临时目录，设备重启后可能清空。
- 两个标签各有一个 **清空日志** 按钮。运行中的容器会短暂重启；维护日志只清除操作记录；数据卷保留。

安装失败日志：`/tmp/sub-store-run-install.log`。

## 数据与更新

数据保存在 Docker 默认 local 命名卷 `sub-store-data`，实际位置由 Docker Root Dir 决定；无需手动创建宿主机目录。

```sh
sub-storectl storage
docker info --format '{{.DockerRootDir}}'
docker volume inspect sub-store-data
```

更改 Docker Root Dir 不会自动迁移已有数据。重启和更新容器会保留数据卷。

进入 **更新维护**，点击 **检查更新**。系统先读取远端镜像清单，比较当前平台的镜像版本；只有发现变化才拉取并重建容器，镜像不变时不操作容器。检查失败时保留当前容器，不尝试拉取。配置变更通过 **保存并应用** 生效。

随后检查 GitHub 插件；有新版本时下载 `.run`，校验 SHA-256 后仅更新 LuCI 插件。两项更新互不阻断，数据卷保留。插件升级并核实版本后，页面会在 5 秒后刷新。插件版本和 Sub-Store 应用版本独立。

镜像更新成功后自动清理本次替换的旧容器、旧镜像及其不再使用的镜像层。旧镜像被其他容器使用或带有其他仓库引用时保留；清理失败不影响更新。数据卷、挂载目录、其他镜像和构建缓存不清理。

导出数据：目标路径必须是绝对路径，所在目录需已存在。导出期间会暂停整个容器；运行中的容器完成后自动恢复，已停止的容器保持停止。

导出包可能包含订阅地址、GitHub Token 和同步凭证，应按敏感文件保存。

```sh
sub-storectl export-data /mnt/path/sub-store-data.tar.gz
```

## 常用命令

```sh
sub-storectl status       # 服务状态
sub-storectl health       # Docker 健康状态
sub-storectl app-version  # 从后端 API 读取版本，失败时回退到容器日志
sub-storectl logs         # 运行日志
sub-storectl start        # 启动
sub-storectl stop         # 停止
sub-storectl restart      # 重启
sub-storectl update       # 更新官方镜像
sub-storectl update-all  # 同时检查并更新镜像和 LuCI 插件
sub-storectl rotate-key   # 轮换 API 随机路径
```

## 远程访问

安装器不会配置 DDNS、端口转发或防火墙规则。远程管理通常只需让前端端口可达；公开访问地址只影响管理链接和 CORS 配置，不会自动创建 DNS 或网络规则。

默认使用 HTTP。随机路径没有自动过期时间，完整管理地址应妥善保管。

## 卸载

```sh
sub-storectl remove-container          # 移除容器，保留 LuCI 和数据
sub-storectl uninstall --keep-data     # 卸载插件，保留数据卷
sub-storectl uninstall --delete-data   # 卸载并删除数据卷
```

`--delete-data` 会永久删除 Sub-Store 数据卷。

## 常见问题

| 问题 | 先检查 |
|---|---|
| 安装失败 | `/tmp/sub-store-run-install.log`、软件源和镜像网络 |
| 页面无法打开 | 端口、网络转发和浏览器控制台 |
| 整页白屏 | 浏览器控制台、缓存和扩展 |
| 后端连接失败 | 使用完整管理地址，确认 API 随机路径未被更改 |
| Docker 镜像更新失败 | 查看维护日志；新容器启动失败时程序会尝试恢复旧容器 |
| LuCI 插件更新失败 | 查看维护日志和安装日志 |
| 同步失败 | Sub-Store 中的凭证、任务状态和远程平台连接 |
