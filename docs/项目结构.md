# 项目结构

本项目为 OpenWrt/iStoreOS 提供 LuCI 管理界面和 `.run` 安装包；Sub-Store 前后端由官方 Docker 镜像运行。

## 组成

| 部分 | 主要文件 | 职责 |
| --- | --- | --- |
| LuCI 页面 | `run/payload/root/www/luci-static/resources/view/sub-store/manage.js` | 服务概览、端口与访问设置、日志切换、服务控制、更新操作。 |
| LuCI 菜单与权限 | `run/payload/root/usr/share/luci/menu.d/luci-app-sub-store.json`、`run/payload/root/usr/share/rpcd/acl.d/luci-app-sub-store.json` | 注册“服务 → sub-store”入口；限制页面可读写的 UCI 配置及命令。 |
| 服务控制 | `run/payload/root/etc/init.d/sub-store`、`run/payload/root/usr/bin/sub-storectl` | 对接系统服务管理；负责 Docker 容器生命周期、端口、API 随机路径、数据卷、访问地址及导出。 |
| 状态与后台任务 | `run/payload/root/usr/lib/sub-store/status`、`job.sh` | 为 LuCI 提供状态、版本、日志等信息；将耗时操作排队执行并记录结果。 |
| Docker 与更新辅助 | `healthcheck.js`、`app-version.js`、`plugin-update`、`permissions.sh`、`cron.sh` | 检查前端/API可用性和应用版本；检查或安装 LuCI 更新；设置目录权限和同步计划。 |
| 安装包 | `run/payload/install.sh`、`run/payload/root/` | 安装 LuCI 文件和配置，准备 Docker 服务；安装器本身由构建脚本打包为 iStore 可上传的 `.run`。 |
| 构建与发布 | `.github/workflows/build-run.yml`、`scripts/build-run.sh`、`scripts/release.py`、`scripts/release_version.py` | 手动分配或续用版本，运行检查，构建 `.run` 与 SHA-256 文件并发布 GitHub Release。 |
| 自动化测试 | `tests/` | 检查 LuCI 页面、状态数据、容器与数据卷、更新、安装回滚、权限、Cron 和发布版本规则。 |
| 用户文档 | `README.md`、`docs/使用笔记.md` | 提供项目简介、安装入口、配置、命令、更新和故障排查说明。 |

## 运行关系

```text
浏览器
  └─ LuCI 页面 manage.js
       ├─ 只读查询 → status
       └─ 服务操作 → job.sh → sub-storectl → Docker → 官方 xream/sub-store 镜像
                                             └─ sub-store-data 命名卷保存数据
```

安装时由 `install.sh` 部署 LuCI 页面、菜单、ACL 和设备侧脚本。服务启动后，`sub-storectl` 使用 Docker 命名卷保存数据；卷的实际路径由设备的 Docker Root Dir 决定。仓库不构建或修改 Sub-Store 官方镜像。

## 发布流程

在 GitHub Actions 手动启动 `Build sub-store installer`，选择 Patch、Minor 或 Major。工作流先检查官方镜像和项目代码，再生成版本化 `.run` 安装器及 `.sha256` 校验文件，验证后发布 Release。普通代码推送不会发布安装包。
